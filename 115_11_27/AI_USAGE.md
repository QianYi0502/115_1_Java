

\# 第八週 AI 使用紀錄



日期：2026/11/27



\## 使用工具與來源



\- 教師設計的模擬 AI 回覆。

\- ChatGPT：協助理解程式、設計測試案例、修正程式及整理紀錄。



\## 使用目的



理解 Java 繼承、方法覆寫、多型及動態繫結，並驗證模擬 AI 提供的程式是否符合需求。



\## 教師模擬 AI 建議



模擬 AI 宣稱，在 HeavyRover 新增同名的 private explore()，父類別的 execute() 就會自動使用該方法。



此建議來自教師設計的錯誤範例，並非真實 AI 服務輸出。



\## 預測與實際驗證



依 Java 方法覆寫規則，private 方法不能被子類別覆寫，因此預期探索產量仍為 2。



使用 HeavyRoverTry 進行測試，實際出現兩項不符：



1\. 探索後：6/5/2/1，預期 6/6/2/1。

2\. 完成後狀態維持：6/5/2/1，預期 6/6/2/1。



\## 錯誤診斷



子類別的 private explore() 是獨立方法，並未覆寫父類別的方法，因此父類別的探索流程不會呼叫它。



\## 本人修正方式



刪除錯誤的 private explore()，改為：



&#x20;   @Override

&#x20;   protected int exploreYield() {

&#x20;       return 3;

&#x20;   }



保留原本的 drill() 與父類別程式，不重新撰寫探索流程。



\## 修正後重測



重新執行同一個 HeavyRoverTry。



探索後及完成後狀態均為 6/6/2/1，15 項測試比對全部相符。



\## 採納與拒絕理由



拒絕模擬 AI 的 private explore() 建議，因為不符合 Java 方法覆寫規則。



採納覆寫 exploreYield() 的修正方式，因為可以保留父類別的能源管理、樣本更新與行動計次流程。



\## 補強 Prompt



請在 HeavyRover 使用 @Override 覆寫 protected int exploreYield()，不帶參數並固定回傳 3。

不得在此方法內扣除能源、增加樣本或計算行動次數。

初始能源 20、樣本 0，執行 {1,1,2} 時，預期能源 8、樣本 6、行動次數 2、已讀步數 2。

初始能源 6、樣本 2，執行 {1,3} 時，預期能源 0、樣本 5、行動次數 1、已讀步數 1，任務成功。



\## AI 使用反思



AI 可以協助理解程式和找出錯誤，但不能只因為程式可以編譯就認為答案正確。應先確認類別契約與方法簽名，再透過實際測試驗證結果。
